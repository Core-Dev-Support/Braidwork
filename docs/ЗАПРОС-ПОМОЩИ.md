# Braidwork — задача для сторонней модели

## Что это

Кроссплатформенное приложение для связи устройств в локальной сети без сервера
и без аккаунтов, конкурент Apple Continuity / Phone Link. Ядро на Rust
(`cdylib`, вызывается через C ABI и JNI), клиент на Kotlin/Compose.

Требования: Android 6+, Windows 10/11, Linux (KDE/GNOME), слабое железо, низкий
расход батареи, интерфейс на русском.

## Репозиторий

https://github.com/Core-Dev-Support/Braidwork

Сборка только на CI, локально Kotlin не компилируется. Релизы в GitHub Releases,
тестирует пользователь на двух телефонах Xiaomi.

## Текущее состояние

Работает и проверено на живых телефонах:

- обнаружение устройств в локальной сети по широковещанию UDP;
- имя устройства из модели (`Build.MODEL` + производитель);
- живучесть канала при сворачивании приложения (foreground-сервис);
- честное состояние «Рядом, не подключено» вместо ложного «Офлайн»;
- версия приложения из тега git;
- обмен ключами Noise XX: TCP-соединение открывается, рукопожатие проходит,
  переход в защищённый канал происходит.

## Что не работает

Соеединение устанавливается и рукопожатие проходит, но в интерфейсе может
показываться «канал не установлен» — это была исправленная ошибка устаревшего
снимка на экране. Актуальная проблема: наблюдались обрывы соединения сразу после
завершения рукопожатия.

## Ключевые файлы

- `core/src/transport/lan.rs` — канал LAN: приём, рукопожатие, кадрирование.
  Здесь сосредоточена вся проблема.
- `core/src/transport/mod.rs` — общий интерфейс транспортов, события.
- `core/src/abi_transport.rs` — C ABI транспорта.
- `core/src/frame.rs` — заголовок кадра и накопитель входящих байтов.
- `core/src/session.rs` — обёртка над Noise XX.
- `core/include/braidwork_core.h` — статический контракт, сверяется на CI.
- `client-android/app/src/main/java/com/naua_braidwork/app/DeviceDiscovery.kt` —
  владелец канала на стороне клиента.
- `STATUS.md` — хронология решений и найденных дефектов.

## Что нужно выяснить

1. Почему соединение закрывается сразу после успешного рукопожатия.
2. Есть ли в `pump_peers` / `обработать` / `шаг_рукопожатия` ошибка порядка
   операций: сокеты неблокирующие, чтение и запись в одном проходе.
3. Не теряется ли сообщение, на котором рукопожатие завершается: инициатор в
   Noise XX заканчивает отправкой третьего сообщения и не ждёт четвёртого.
4. Не закрывается ли соединение из-за того, что инициатор переходит в фазу
   данных сразу после отправки третьего сообщения, не дождавшись ничего.
