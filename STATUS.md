## Диагноз

Диагноз получен, но не исправлен. Две независимые причины.

### 1. Длина идентификатора

`device_id` — это base32 от 16 байт, то есть **26 символов**, а не 16 байт.
Тесты утверждали `as_bytes().len() == 16`, отсюда падение.

`fingerprint()` печатает hex от первых 16 символов строки, то есть 32 символа
с пробелами — длина 35, а тест ждал 19.

Решение, которое надо принять осознанно, а не подгонкой теста: сколько
символов показывать пользователю при сверке. Разумно 4 группы по 4 hex-символа
от первых 8 байт — это ровно 19 символов с пробелами. Значит `fingerprint()`
должен брать первые 8 байт, а не 16 символов.

### 2. Порядок шагов рукопожатия

Ответчик после чтения первого сообщения **сразу пишет** своё, поэтому
`resp.step(&msg1)` возвращает `Send`, а не `WaitForInput`. Тест ждал другого.

Правильная последовательность:

```
msg1 = init.step(&[])   -> Send
msg2 = resp.step(&msg1) -> Send          (ответчик читает и отвечает)
          init.step(&msg2) -> Complete   (инициатор читает и завершает)
```

Лишний вызов `resp.step(&[])` в тесте убрать. Из-за него не проходили все
семь падших тестов сессии — они падали на разборе `handshake_pair`, а не по
своей сути.

## Среда

Rust 1.99, цели под 4 ABI Android и Windows x64/ARM64.
Visual Studio Build Tools 2022 и protoc установлены.

Ядро собирается только из `cmd` с вызовом `vcvars64.bat`, иначе не находится
линкер. Скрипта для этого пока нет — причина неудобства локальных сборок.

`protoc` не работает с кириллицей в путях, обход сделан в `build.rs` копированием
схемы во временную папку с латинским именем.

## Что делать дальше по порядку

1. Починить девять тестов по диагнозу выше. Ничего нового не писать, пока
   они не зелёные.
2. Прогнать clippy и `cargo fmt`, они включены в CI и наверняка найдут
   замечания: в коде остались предупреждения о ненужном `mut`.
3. Прогнать оба пайплайна на GitHub и убедиться, что APK собирается.
4. Дальше по плану: транспорт LAN, затем SoftAP.

## Чего делать нельзя

- Плагин в PowerShell с `Set-Content` портит кириллицу в исходниках. Уже
  портил `crypto.rs` один раз. Правки только через `edit` или `write`.
- Не угадывать API библиотек. `snow` и `ed25519-dalek` уже удивили дважды:
  смотреть исходник в `~/.cargo/registry/src` до написания кода.
